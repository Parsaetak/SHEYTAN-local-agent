SHEYTAN-Local-Agent — v1.1.5Z Phase 3 Replacement Package
=========================================================

Contents
--------
This package contains EVERY new and modified repository file required to
replace the v1.1.5Z Phase 2 repository state with v1.1.5Z Phase 3, at
repository-relative paths. No deleted files exist in this release. To
apply: unzip over a v1.1.5Z Phase 2 checkout (or clean clone at the base
commit), overwriting files; then run the verification commands below.

What changed (honest scope)
---------------------------
Structural improvements (all verified by the suites below):

  1. Unified loading pipeline. One owner per stage:
     Source/Input → Loader → Normalizer → Chunker → Cache → Retriever →
     Context Builder. The legacy attachments writeObjectAtomic /
     buildChunks paths were removed after their last callers moved to
     the shared flow. No duplicate loaders remain.

  2. Chunk engine (internal/chunking/chunker.go, processing version v2).
     ChunkText: single interval pass (no rescanning, no repeated
     copying), exact byte offsets recorded during the pass, configurable
     overlap (rune-aligned, progress-guaranteed) and max-chunk count
     without unbounded memory, UTF-8-rune-aligned hard splits,
     deterministic chunk IDs from source content hash + processing
     parameters + chunk content hash, full metadata per chunk (source
     identity, byte range, estimated tokens, sequence index, total
     chunks, processing version, preview). SplitParagraphs keeps its
     public behaviour; with ASCII input its cuts are byte-identical to
     the pre-Phase-3 algorithm (equivalence test pinned). Lossless
     reconstruction preserved for Overlap=0.

  3. Cache as a data-layer primitive (internal/contextcache, processing
     version v4). GetOrCompute[T] single-flight coalescing (compute
     outside the mutex, joiners share the result, panics propagate
     without wedging the slot); oversized-entry guard — Put now returns
     bool and rejects a single entry above the per-entry bound instead
     of pinning the cache above its byte bound; exact insert
     accounting; new measured counters (inserts, coalesced,
     oversizedRejected). Content keys, version invalidation, config
     fingerprints, LRU and both bounds unchanged.

  4. Attachment loading (internal/attachments). Streaming staging:
     Add spools to a temp object while hashing and keeps only a
     16 KiB sniff head + one pooled 128 KiB buffer in RAM — binaries
     and images are never fully buffered; oversize/empty rejects happen
     during the copy and never touch the object store. Retrieval: each
     attachment's object is read AT MOST ONCE per call (verified by
     test); objects above the 32 MiB per-call retention cap degrade to
     exact byte-range reads. NormalizeText zero-copy fast path.
     Measured resource counters (ResourceUsage). Caps, content
     addressing, symlink refusal, dedupe, provenance and error strings
     unchanged.

  5. Context construction instrumentation. contextplan.Plan gained
     measured PromptBytes; the orchestrator logs a context-metrics line
     per turn (bytes, tokens, pressure, elided, recalled, attachments);
     the API server logs measured retrieval stats per turn
     (attachments considered, chunks considered/selected, bytes,
     object reads, cache hit). Wire/UI contracts unchanged (additive
     JSON fields only).

  6. Persistent memory (internal/memory). Append-aware parsed cache:
     appends, deletes and clears fold into the cache and refresh the
     stat key — remember→recall cycles no longer re-parse the file
     (tests assert ZERO full re-parses after warmup). Search scores the
     cached entries read-only and copies only matches. Trust rules
     untouched: M1–M7, quarantine, external downgrade and
     authoritative-user-fact logic are the same code paths, re-verified
     by the full trust test suite.

  7. Other loading paths. llm.ReadModelCard reads through a 64 KiB
     buffered window (skipping a tokenizer array used to issue one
     unbuffered syscall per string); the API model-card cache is keyed
     by path+size+mtime and bounded (512 entries).

  8. Concurrency. No new goroutines. The only new primitive is the
     cache in-flight map (mutex + WaitGroup; compute runs without the
     lock). Full race suite passes (see verification).

Measured benchmark results (same inputs, 2-vCPU Linux container,
Go 1.27.1, median of 5 runs; before = pre-Phase-3 algorithm on the
base commit, after = this package):

  chunk derivation (512×4 KiB chunks of a 5.5 MB source):
    before 5.77 ms/op · 10.91 MB/op · 4880 allocs/op
    after  3.64 ms/op ·  2.46 MB/op · 4880 allocs/op
    → 1.6× faster, 4.4× fewer bytes allocated
  memory.Search (5000-entry store):
    before 7.40 ms/op · 7.67 MB/op · 172 allocs/op
    after  3.24 ms/op · 1.53 MB/op ·  90 allocs/op
    → 2.3× faster, 5× fewer bytes
  recall.Search (5000-capsule corpus):
    before 4.78 ms/op · 5.46 MB/op · 15160 allocs/op
    after  2.37 ms/op · 3.17 MB/op ·   124 allocs/op
    → 2.0× faster, 122× fewer allocations
  contextcache hit path: 20.9 ns/op, 0 allocs/op

Structural wins not visible in micro-benchmarks: per-retrieval object
reads drop from N(selected chunks) to ≤1 per attachment; binary/image
staging peak RAM drops from the full file size (≤64 MiB) to ≤16 KiB +
one copy buffer; remember→recall no longer re-parses the memory file.

Remaining bottlenecks (documented, not hidden): retrieval scoring still
ranks on chunk previews (deliberate v1.1.3Z design); the sha256 of each
chunk dominates the remaining chunking cost (content identity requires
it); the memory store still stats the file on every read by design
(cross-writer correctness).

  Multi-agent redesign                                     = NOT implemented
  Android port / major UI redesign                         = NOT implemented

  Semantic or structural repository retrieval / embeddings = NOT implemented

from Phase 2 continues to work exactly as before (its real-host
integration tests pass unchanged). All existing security controls and
resource bounds remain intact.
