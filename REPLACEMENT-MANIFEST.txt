Native loader implementation summary
------------------------------------
  - GGUF reader (native/engine/src/gguf.*): magic + version validation
    (v2/v3), metadata parsing with hostile-input bounds, tensor-table
    parsing with overflow-checked element products and per-tensor offset
    validation against the data section (exact byte-size checks for
    known GGML types), alignment handling, file-size validation; model
    metadata is never trusted; reads touch only header pages.
  - Memory mapping: whole-file read-only mmap (POSIX) /
    CreateFileMapping (Windows) — lazy access, no eager copy of tensor
    data into RAM, no full-file reads.
  - LoadModel/UnloadModel (native/engine/src/model.*, ABI v2):
    all-or-nothing loading with replace semantics; idempotent unload;
    clean release of mapping/handle on every failure path (verified
    under AddressSanitizer); model states unloaded/loading/loaded/failed
    mirrored on the Go side and reset on every host lifecycle boundary.
  - Memory planning (computed, never allocated): model file / mapped /
    weights (tensor-data span) / workspace estimate (ctx·vocab·4) /
    KV-cache estimate (2·K/V·layers·ctx·emb·2 bytes f16) / fixed 64 MiB
    runtime allowance / overflow-checked total / fit-vs-RAM verdict.
  - Metadata extraction (only values actually read or derived):
    architecture, name, parameter count (read or derived from the tensor
    table), context length, vocabulary size, embedding length, layer
    count, quantization (general.file_type), tensor count, file size.
  - Go exposure: llm.ModelInfo gains additive optional fields
    (State, FileSizeBytes, TensorCount, GGUFVersion, VocabSize,
    EmbeddingLength, LayerCount, KV/workspace/total memory estimates);
    the llama.cpp model path is untouched (leaves the new fields zero).

Known limitations
-----------------
  - Native generation is NOT implemented (this phase loads and plans,
    nothing else): Generate/StreamGenerate return ErrNotImplemented,
    GenerationCapable() stays false, every generation request runs on
    llama.cpp. Loading a model does NOT enable generation.
  - The memory plan is arithmetic on parsed metadata; real buffer
    allocation arrives with the inference phase.
  - GGUF v1 containers are rejected; GGML tensor types outside this
    build's size table are validated leniently (offset-in-range only) —
    never guessed.
  - The contextLength load option plans memory only; no context buffers
    exist yet.
  - The native host binary is not shipped or auto-downloaded; build it
    from native/engine/ and place it in {DataDir}/bin/ (or set
    nativeEnginePath).
  - As with any mmap consumer, a model file shrinking while mapped is an
    OS-level hazard; SHEYTAN opens model files read-only and never
    writes to them.
